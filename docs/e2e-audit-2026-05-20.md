# E2E Wiring Audit — R74 through R82 (2026-05-20)

Triggered after the user observed every new feature seemed to land as
"scaffolding only" — UI compiled and rendered, but data didn't survive
cold start. Audit checked all 7 new feature areas shipped in R74-R82
for FE → BE → DB connection.

## Method

For each new persisted field or new entity:
1. Does the FE type exist? (`src/domain/*.ts`)
2. Is there a DB column for it? (migration in `supabase/migrations/`)
3. Is the Row type updated to include it? (`src/lib/database.types.ts`)
4. Does the FE→BE mapper write it? (`updateX` mutator in `AppState`)
5. Does the BE→FE mapper read it back? (`src/lib/mappers.ts`)

A field needs all 5 to round-trip. Missing #4 → data disappears on
cold start. Missing #5 → cold start hydrates without it. Missing #2 →
BE write silently fails (CHECK constraint or table-level RLS).

## Bugs found

### Bug 1 — `country` CHECK constraint rejects 'US' (CRITICAL)

`business_settings.country` CHECK was added in `20260415000001_business_profiles.sql`
with the locked list `('NL','DE','FR','ES','IT','UK')`. R74 added `'US'` to
the FE `CountryCode` union and routed US contractors through onboarding,
but no migration ever widened the CHECK. Every UPDATE/INSERT with
country='US' would have rolled back the entire row.

**Fix**: `20260520000003_business_settings_us.sql` drops the existing
constraint and re-creates with 'US' included.

### Bug 2 — Three US fields silently dropped on persist (CRITICAL)

R74 added `state`, `routingNumber`, `bankAccountNumber` to
`BusinessProfile`. The onboarding UI wrote them. AppState updated React
state. But:

- No migration added the corresponding `business_settings` columns.
- The `dbUpdates` mapper in `updateBusinessProfile` had no branches for
  these three fields. They were silently dropped on BE write.
- The `businessSettingsToProfile` mapper didn't read them either, so
  even if they'd persisted, cold start would have dropped them.

Net effect: a US contractor types EIN + TX + routing # + account # in
onboarding → reopens the app the next day → empty. Every US invoice PDF
generated post-cold-start would have shipped with blank Routing # /
Account # fields.

**Fix**: `20260520000003_business_settings_us.sql` adds the three
columns. `AppState.updateBusinessProfile` extended with mapper entries
for `state`, `routing_number`, `bank_account_number`. `mappers.ts`
extended with hydration entries.

### Bug 3 — `licenses` field not persisted (HIGH)

R79 added `BusinessProfile.licenses[]` and migration
`20260520000001_contractor_licenses.sql` added the `business_settings.licenses
jsonb` column. R80 added a UI screen that called
`updateBusinessProfile({licenses: [...]})`. But:

- `dbUpdates` mapper had no branch for `licenses` — silently dropped.
- `businessSettingsToProfile` mapper didn't read it either.
- Vandaag amber warning card would have run on an empty array.
- Daily push digest would have queried `business_settings.licenses`
  and found NULL — no warnings ever fired.

**Fix**: AppState mapper + mappers.ts hydration both extended with
`licenses` round-tripping. `BusinessSettingsRow` row type extended.

## Systemic learning

This is the third recurrence of the same bug class (R66r24, R66r34, R83).
Every new persisted field needs all five files updated in lockstep or
it's scaffolding only. Added as MEMORY.md workflow rule #8 and
learnings.md entry #50 — see those for the full checklist + audit
grep pattern.

## What's still dormant (deliberately)

- **SMS service** (`smsService.ts`) — feature-flag `sms_us` defaults
  off. Edge function deployed but waits on `TWILIO_*` secrets. No
  business-logic callers yet — UI surfacing of "On my way" text is
  follow-up work.
- **TaxJar service** (`salesTaxService.ts`) — feature-flag
  `tax_real_lookup` defaults off. Edge function deployed but waits on
  `TAXJAR_API_KEY`. No invoice-builder integration yet — the invoice
  PDF still uses the static state rate.
- **US App Store screenshots** — strings dictionary built
  (`video/src/data/screenshotStrings.ts`) but composition JSX not yet
  rewritten to consume it. `/us` reuses `-en.png` from R66r73.

These are real dormant features by design — flipping them on requires
operator-side credential setup, not more code. Each is structurally
ready to activate.
